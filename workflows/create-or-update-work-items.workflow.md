# Create or update work items

**Trigger:** An approved delivery plan needs GitHub Issues, GitHub Projects, or
Azure DevOps work items.

**Lead role:** Project delivery manager.

## Stages
1. Verify target organization/project/repository and available integration.
2. Search remote items for duplicates and inspect templates/field conventions.
3. Draft issue/work-item title, scope, acceptance criteria, dependencies, and labels.
4. Present a preview of every create or update, including its remote target.
5. Obtain explicit approval per remote write; execute only approved operations.
6. Read back changed items and report canonical IDs/URLs and failures.

## Outputs
Proposed and approved operations, resulting tracker links, read-back evidence,
and any items left unsynchronized. Never create, update, assign, or close work
items silently.
