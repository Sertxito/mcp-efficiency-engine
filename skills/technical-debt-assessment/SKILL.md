# Technical debt assessment

## Procedure
1. Define system boundary and debt categories in scope.
2. Record each item with source evidence, affected boundary, and fact/hypothesis
   status.
3. Describe demonstrated business/technical impact and confidence; keep
   unmeasured cost-of-delay explicit.
4. Prioritize by impact, likelihood, urgency, dependencies, and effort evidence.
5. Record accepted debt with rationale, owner, and review trigger where known.

## Output
Traceable register, priority rationale, unknowns, accepted debt, and next action.
Do not publish numeric heatmaps or monetary estimates without a stated method.
