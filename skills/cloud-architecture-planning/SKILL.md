# Cloud architecture planning

## Procedure
1. Establish workload shape, service objectives, data classification, regions, and constraints.
2. Confirm provider and existing platform conventions; do not assume a provider or subscription.
3. Compare viable architectures for reliability, security, performance, operability, and cost.
4. State scale/capacity assumptions and cost-estimate scope, date, and uncertainty.
5. Describe boundaries and deployment topology with an appropriate diagram or structured list.
6. Identify migration stages, dependencies, validation gates, rollback limits, and approvals.

## Output
Options, assumptions, trade-offs, estimated cost/capacity basis, topology, risks,
and an evidence-backed recommendation or open decision. Provisioning and live
configuration changes require separate explicit approval.
