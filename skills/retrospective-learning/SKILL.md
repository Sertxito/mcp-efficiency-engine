# Retrospective learning

## Procedure
1. Start from verified execution, test, incident, or evaluation evidence.
2. Separate one-off causes from recurring patterns and state confidence.
3. Propose the smallest reusable change to a skill, workflow, policy, or runbook.
4. Link the proposal to sources and define how its effect will be evaluated.
5. Persist it only after the designated owner explicitly approves it.

## Output
Evidence, observed pattern, proposal, expected benefit, risks, owner, and
evaluation criterion. Never store secrets or unsupported causal claims.
